## 2026-10-20 - Windows build + cross-platform netplay harness

- **feat(autopilot):** build-only AI for a human player. Ctrl+Shift+A toggles, Ctrl+Shift+L cycles Easy/Normal/Hard;
  `MSG_SET_AUTOPILOT` goes through the network command stream so all machines flip on the same logic frame (verified in sync
  Linux/Windows). `AISkirmishPlayer` gets an autopilot-only update (base building + economy, no army) and
  `adoptExistingBase()`; `adjustBuildList` gained a flag because it destroys the start command center for AI players. Added
  `autopilotQueueNextStructure` (cheapest-first build planner standing in for the skirmish scripts a human does not have, with
  recursive prerequisite queuing); verified Linux+Windows in sync, bases grow 1 -> 7-10 buildings with income.
- **feat(cheats):** opt-in `-cheats`: Ctrl+Shift+M (+$10,000), Ctrl+Shift+G (+1 general's point) via `MSG_CHEAT_GIVE`; machines
  without the flag skip it, which desyncs visibly.
- **fix(netplay):** the headless harness now appends `MSG_FRAME_TICK` like `GameClient::update`; without it the network never
  left PRE-GAME, commands were dropped and headless instances were independent simulations. Earlier headless "in sync" results
  predate this fix.
- **build(win32):** first working MSVC build of Zero Hour on a remote Windows box (`scripts/remote-build.sh`, ssh alias
  `vadapuppy`). MinGW links but the exe needs the debug `d3dx8d.dll`; the MinGW-incompatible static `d3dx8.lib` rules that route
  out, so MSVC is the Windows toolchain. Needs `-DSAGE_USE_DX8=ON -DRTS_BUILD_OPTION_SAGE_PATCH=OFF` (SAGE_USE_DX8 is undefined by
  default and silently selects the Linux DXVK headers).
- **fix:** MinGW compile fixes (`__int64` typedef guards, `socklen_t`, `<sys/stat.h>` in FTP.cpp).
- **feat(netplay):** `-lanhost` / `-lanjoin` headless LAN harness (`LanNetplayHarness.cpp`) + `tools/netplay/run-netplay.sh`.
  First Linux-host / Windows-join match with two Hard AIs: 9000 frames, state CRCs and final stats identical on both machines.
  LANAPI menu callbacks skip their UI work while the harness runs. Details: `tools/netplay/README.md`.
- **netplay results:** headless+headless (5 and 8 game-minutes, observers and real players vs Hard AIs; NOTE these ran before the
  MSG_FRAME_TICK fix above, so they were independent simulations, not lockstep - to be re-run) and windowed+windowed
  (Linux desktop + Windows laptop, screenshots every 30s) are in sync on every per-minute state CRC and final stats. Mixing a
  headless and a windowed instance desyncs from the first checkpoint on both platforms, so it is a headless-vs-windowed
  simulation difference, not a Linux-vs-Windows one (uninvestigated). Windowed replay playback of a known-good replay passes.
- Linux in-engine screenshots are written with a literal backslash in the file name (task spawned to fix the path building).
- Replay baseline: the two custom-map macOS replays play to the end on both Linux and Windows; `macos_2p_vanilla_map` fails at
  frame 0 with the same CRC on both platforms (replay/map issue, not platform).
